## 3. BRAIN result handling

### 3.1 Units
- Turnover, returns, drawdown are stored as fractions (0.2578), not percents.
- The screenshots show percents. Convert on ingest. Add a unit test for this.

### 3.2 Fields the system may rely on
Only these fields. Anything else is ignored.
Aggregate: sharpe, fitness, turnover, returns, drawdown, margin, sub-universe sharpe and its cutoff, weight concentration, long/short PnL, daily PnL, self-correlation when available, and BRAIN's pass checks.
Yearly rows: year, sharpe, turnover, fitness, returns, drawdown, margin, long count, short count.

### 3.3 Metric validator (metric_validator.py)

Pure functions. Used as a tripwire on every result.

1. `expected_fitness(sharpe, returns, turnover) = sharpe * sqrt(abs(returns) / max(turnover, 0.125))`
   - Check against the reported fitness with tolerance 0.01.
   - Known test values from the screenshots, see section 15.2.
   - If the reported fitness is None, skip. Do not fail.
2. `check_yearly_consistency(aggregate, yearly)`: the aggregate Sharpe should lie within the range of yearly Sharpes. Flag if not. (Information only.)
3. `margin_check(result)`: compute the naive margin = returns / (turnover * 252) * 10000 bps. Record the BRAIN margin and the naive value side by side. Do NOT fail on mismatch. Open question OQ-1 controls this. Emit a `margin_mismatch` note when the ratio is outside [0.8, 1.25] of the reported value.

Output: a list of validation notes. Never raises on a mismatch. Raises only on malformed input.

## 4. Simulator wrapper and BRAIN client (simulator.py, brain_client.py)

### 4.1 BrainClient interface

```python
class BrainClient(Protocol):
    def submit(self, candidate: CandidateRecord) -> str: ...        # returns brain_sim_id
    def poll(self, brain_sim_id: str) -> dict: ...                  # raw response dict
```

Two implementations.

**FixtureBrainClient.** Reads JSON files from `tests/fixtures/brain_results/`. `submit` returns a fixture id. `poll` returns the stored raw response. Used by all tests and by the pipeline in this phase.

**RealBrainClient.** Stub only. Every method raises `NotImplementedError("BRAIN API not yet integrated. Needs a real response sample. See OQ-2.")`. Do not write any HTTP code.

### 4.2 Simulator wrapper steps

1. **Validate locally before submit.** Reject with a `status="invalid"` ResultRecord (no client call) when:
   - expression is empty or has unbalanced parentheses
   - region, neutralization, or universe is not in the allowed set
   - delay not in {0, 1}
   - date range overlaps the holdout period (see 5.1)
   - holdout period is not configured: raise `ConfigError`
2. **Submit.** Call `client.submit`. Persist the candidate row and the brain_sim_id before polling. If the process dies here, the next run must find the pending submission and resume polling instead of resubmitting.
3. **Poll.** Loop with a sleep between polls. Honour a `Retry-After` value if the fixture includes one. Stop on complete, failed, or after `max_poll_seconds` (config).
4. **Retry policy.** Retry transient errors (`TimeoutError`, `ConnectionError`) up to `max_retries` (config) with exponential backoff. Never retry validation errors.
5. **Normalize.** Map the raw dict to a ResultRecord. Convert percents to fractions. Missing keys become None.
6. **Validate.** Run the metric validator (3.3). Attach notes.
7. **Persist.** Write the ResultRecord to memory (section 11) before returning.
8. Return the ResultRecord.

### 4.3 Concurrency

Single-threaded in Phase 1 and 2. Add a `max_concurrent` config value (default 1) and a comment that the real limit is account-specific (see OQ-3). Do not implement threading yet.

## 6. Data Scientist (data_scientist.py)

Input: a pandas DataFrame, dates as index, instruments as columns, values as floats (NaN for missing). One datafield, one region, last 252 rows.

Compute and return an AuditRecord:

1. `coverage_median`, `coverage_min`: per day, non-NaN count divided by number of instruments. Median and minimum across days.
2. `update_gap_median_days`: per instrument, the gap in days between consecutive value changes. Median across instruments.
3. `tail_fraction`: per day, fraction of values beyond 3 standard deviations from the cross-sectional median. Average across days.
4. `nan_pattern`: one of `random`, `clustered_by_date`, `clustered_by_instrument`. Method: compare the variance of per-day NaN fractions and per-instrument NaN fractions to what a random mask would give. Document the method in the docstring. Keep it simple.
5. `redundancy`: given a dict of other fields (name to DataFrame), compute the mean over days of the Spearman correlation of cross-sectional ranks. Return the names above 0.9.
6. `recommendation`:
   - `not_usable` if coverage_median < 0.5 or redundancy list is non-empty
   - `usable_with_backfill` if coverage_median < 0.8 or nan_pattern is not random
   - `usable` otherwise
   - Reasons list explaining the choice.

Tests:
- Dense synthetic frame (coverage about 1.0) returns `usable`.
- Sparse synthetic frame (keep about 15% of values) returns `not_usable` or `usable_with_backfill`.
- A frame that is a copy of another field returns the redundancy flag.
- A frame with NaNs grouped by date returns `clustered_by_date`.

## 7. Evaluator (evaluator.py)

Input: ResultRecord. Output: DecisionRecord. No judgment, only rules.

### 7.1 Hard gates, run in this fixed order

1. `sharpe`: pass if sharpe > gates.sharpe_min
2. `fitness`: pass if fitness > gates.fitness_min
3. `turnover_range`: pass if turnover_min <= turnover <= turnover_max (both bounds; the lower bound matters)
4. `self_correlation`: pass if self_correlation < gates.self_correlation_max. If self_correlation is None, `passed=None`, and the decision is `pending`, not reject.
5. `sub_universe`: pass if sub_universe_sharpe >= sub_universe_cutoff, where the cutoff comes from the result. If either is None, `passed=None`.
6. `weight_concentration` and `drawdown`: soft checks. Recorded here, decided by the risk manager.

Gates 1 to 4 are hard. A failed hard gate blocks acceptance. Gate 5 is hard when a cutoff is present, since BRAIN's own pass list includes it.

If any result has `status != complete`, the decision is `reject` with failure_class `incomplete`.

### 7.2 Failure classification

Priority order, fixed:
1. self_correlation
2. turnover
3. sharpe
4. fitness
5. sub_universe
6. concentration
7. drawdown
8. leg_imbalance
9. weak_year
10. other

The failure_class is the first failed item in this order. If nothing failed, `none`.

### 7.3 Decision

- All hard gates passed (True) and risk veto is False: `accept`
- Hard gate failed and failure_class has a playbook entry: `repair`
- Hard gate failed and no playbook entry: `reject`
- Any hard gate is None (not evaluable): `pending`
- Risk veto True on an otherwise passing result: `reject` with the veto reasons (the risk manager decides; see 8.2)

### 7.4 Tests

Use the screenshot values as the "all pass" case:
- sharpe 1.68, fitness 1.11, turnover 0.2578, sub_universe_sharpe 1.07, cutoff 0.73, self_correlation 0.1 gives `accept` (before risk).

One failure each, all other values passing:
- sharpe 1.10 gives `reject` with failure_class `sharpe`
- turnover 0.85 gives `repair` if the playbook has a turnover entry, failure_class `turnover`
- self_correlation 0.8 gives `repair` or `reject` depending on playbook, failure_class `self_correlation`
- sub_universe_sharpe 0.5 with cutoff 0.73 gives failure_class `sub_universe`
- self_correlation None gives `pending`
- status "timeout" gives `reject` with failure_class `incomplete`

## 8. Risk Manager (risk.py)

Each check is a function returning `GateResult`. The manager collects them and returns `(veto: bool, checks: list, reasons: list)`.

### 8.1 Checks

1. **drawdown_depth**: fail if max_drawdown > risk.max_drawdown. Not configured: None.
2. **drawdown_timing**: informational. Record drawdown_date. Flag if it falls in a user-supplied stress window list (config, optional, default empty).
3. **leg_balance**: ratio = min(|long_pnl|, |short_pnl|) / max(|long_pnl|, |short_pnl|). Fail if below risk.leg_balance_min_ratio. Requires both PnL values, else None.
4. **top_pnl_removal**: requires daily_pnl. Remove the top `top_n_pnl_days_removed` days by absolute PnL, recompute annualized Sharpe as mean / std * sqrt(252). Fail if below min_sharpe_after_top_pnl_removal. If daily_pnl is None, None.
5. **weight_concentration**: fail if above risk.weight_concentration_max.
6. **sub_universe**: already covered by the Evaluator gate. Do not duplicate. Reference the gate result instead.
7. **weak_year**: fail if any yearly Sharpe is below weak_year_sharpe_floor, or if max minus min yearly Sharpe is above max_yearly_sharpe_spread. Either config null means None for that half. Yearly rows empty means None.

### 8.2 Veto rule

Veto is True if any check has passed=False. Checks with None do not veto but are listed as "not evaluated" in reasons. The Evaluator must read veto before accepting.

### 8.3 Tests

- A result with long_pnl 10 and short_pnl 0.5 with a leg balance floor of 0.3 vetoes on leg_balance.
- A daily_pnl series where the top 10 days carry most of the profit fails top_pnl_removal.
- With all thresholds null, every check returns None and veto is False. Reasons list says "not configured" for each.

## 9. Diversity Manager (diversity.py)

Needs daily PnL. Works on pandas Series with dates as index.

Functions:
1. `pnl_matrix(series_dict)`: align on dates, inner join, drop rows with any NaN. Return DataFrame. Require at least 60 overlapping days, else raise `InsufficientHistoryError`.
2. `candidate_correlations(candidate_pnl, pool_matrix)`: Pearson correlation of the candidate against each pool column. Return max, mean, and the per-alpha dict.
3. `pool_sharpe(matrix)`: equal-weight combined PnL = row mean across columns. Annualized Sharpe = mean / std * sqrt(252).
4. `marginal_gain(candidate_pnl, pool_matrix)`: pool_sharpe(pool plus candidate) minus pool_sharpe(pool). If the pool is empty, the gain is the candidate's own Sharpe.
5. `effective_n(matrix)`: correlation matrix of columns, eigenvalues (use numpy.linalg.eigvalsh), then N_eff = (sum of eigenvalues)^2 / sum of squared eigenvalues. Note: eigenvalues of a correlation matrix sum to its dimension, so this formula is valid.
6. `admission_check(candidate_pnl, pool_matrix)`:
   - reject if max correlation > diversity.max_pool_correlation
   - if min_marginal_pool_sharpe_gain is null, return `passed=None` for the gain and note "not configured"
   - returns a GateResult list and an admit flag (admit only if no hard failure and the gain check is not failed)

Tests:
- A near-duplicate of an existing column (correlation 0.99) is rejected.
- An independent Gaussian series of the same length is admitted (with the gain check set to None).
- Effective N for 10 identical columns is about 1. For 10 independent columns it is about 10.
- Fewer than 60 overlapping days raises `InsufficientHistoryError`.

## 10. Overfitting Auditor (auditor.py)

### 10.1 Variant counting
- `register_variant(family, candidate_id)`: increments a counter per family. Counts every simulation, including failures and repairs. Persisted in memory (section 11).

### 10.2 Deflation method (document this in the module docstring)

Deflate the best observed Sharpe in a family by the expected maximum Sharpe that N zero-edge strategies would produce by chance.

- Let N = number of variants in the family, T = years of data in the backtest.
- Standard error of an annualized Sharpe estimate: `se = sqrt((1 + 0.5 * S^2) / T)`, where S is the observed Sharpe. Use the candidate's own Sharpe.
- Expected maximum of N independent standard normal draws (Bailey and Lopez de Prado approximation):
  `E_max(N) = (1 - g) * Phi^-1(1 - 1/N) + g * Phi^-1(1 - 1/(N*e))`, where g = 0.5772 (Euler-Mascheroni) and Phi^-1 is the inverse normal CDF.
- Deflated Sharpe = S - se * E_max(N).
- For N = 1, E_max = 0 and deflated equals raw.

Implement with `scipy.stats.norm.ppf`. Put the formula and a citation placeholder in the docstring. Note in the docstring that this is an approximation and the write-up should state it.

Tests:
- N = 1 gives deflated equal to raw.
- Simulate 200 zero-mean daily return series for 5 years, compute each Sharpe, take the best. The deflated best must be lower than the raw best by a clear margin (assert at least 0.5 Sharpe units lower).

### 10.3 OS/IS tracking
- `record_os_is(alpha_id, family, is_sharpe, os_sharpe)`: store both. Ratio = os / is when is > 0, else None.
- `family_ratio(family)`: mean ratio over admitted alphas in the family, ignoring None.
- `flag_family(family)`: returns True if family_ratio < auditor.os_is_ratio_floor. If the floor is null, return None.

Tests with synthetic values. A family with ratios [0.9, 0.8] is not flagged for floor 0.7. A family with [0.2, 0.3] is flagged for floor 0.7.

## 13. Orchestrator and Research Loop (orchestrator.py, research_loop.py)

### 13.1 Orchestrator: Thompson sampling with floor quotas

Arms are tuples (dataset, region, prompt_version). In Phase 2 prompt_version is a placeholder string.

State per arm: successes, failures. Prior Beta(1, 1).

- `allocate(budget, floor_share)`:
  1. Guarantee each arm at least `floor_share * budget / number_of_arms` slots (floor_share between 0 and 1, default 0.2). Use integer rounding and document it.
  2. Distribute the remaining slots by sampling each arm's Beta(successes + 1, failures + 1) posterior and assigning slots to the top samples, one slot at a time (re-sample after each assignment or use a deterministic approach). Pick one method, document it.
  3. Accept a random seed for reproducible tests.
- `update(arm, passed)`: increment successes or failures.
- Reward for the bandit is the pass rate. Novelty weighting is a Phase 3 concern; do not implement it yet.

Tests (fixed seed):
- With one arm far better than the rest, it gets the most slots.
- With floor_share 0.2 and 5 arms, every arm gets at least floor slots even when one arm dominates.
- Allocation sums exactly to budget.

### 13.2 Research Loop

- `experiment_id(candidate)`: deterministic hash of normalized expression plus settings. Used for duplicate checks.
- `is_duplicate(candidate)`: looks up the hash in memory. Returns True if a result exists for the same hash.
- `assign_lineage(candidate, parent)`: sets parent_id, records generation number.
- `queue`: a simple FIFO of CandidateRecords. `drain(max_items)` returns up to max_items.
- `decide_next(decision)`: maps decision to action. accept goes to pool, repair goes to repair.py, reject goes to memory only, pending goes back to the queue.

Normalize expressions before hashing: strip whitespace, lowercase operator names only, sort nothing else. Document this.

Tests:
- Two candidates with the same expression and settings but different whitespace produce the same hash.
- Duplicate detection returns True after a result is stored.
- Lineage increments generation.
- decide_next routes each decision type correctly.

## 14. Pipeline and CLI (pipeline.py, cli.py)

### 14.1 Pipeline steps for each candidate

1. Check duplicate (research_loop). If duplicate, log and skip.
2. Run simulator wrapper (FixtureBrainClient in Phase 1).
3. Run metric validator notes (already in the wrapper).
4. Run the Evaluator on the result.
5. Run the risk manager (only if the Evaluator did not reject for incomplete status).
6. If accept, run diversity admission against the pool. If it fails, change decision to reject with failure_class `self_correlation`.
7. If accept, run the auditor's variant registration and OS/IS placeholder (no OS data yet, so skip OS/IS).
8. Write the decision to memory. If accept, admit to pool.
9. Print one line: `candidate_id | decision | failure_class | sharpe | fitness | turnover`.

### 14.2 CLI

`python -m alpha_research.cli run --candidates tests/fixtures/candidates/hand_written.json`

Options:
- `--config` path to thresholds.yaml (default config/thresholds.yaml)
- `--data-dir` (default ./data)
- `--client fixture` (only option in this phase; `real` raises NotImplementedError)

Exit code 0 on success, non-zero on config or schema errors.
